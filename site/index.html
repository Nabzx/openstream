The idea

Deny-by-default on line breaks

Most dictation tools treat every target the same. That is fine in a document and dangerous in a shell, where one newline submits a half-typed command or fires off an unfinished message.

OpenStream checks the frontmost app and the focused field before it turns a spoken “new paragraph” into a real break. A break only survives in apps you have put on the allow-list. Everywhere else it is dropped and the words run on.

If a result needs its line breaks — a bullet list, say — and the target cannot take them, OpenStream holds the text for you to paste rather than flattening it into nonsense.

Privacy by construction

Nothing leaves the machine

Transcription and text handling run in local model servers that stay resident while the app is open. There is no account, no cloud endpoint, and no network call on the path from your voice to the cursor.

What it does today

Dictate, edit, cancel — all by voice

Push-to-talk dictation

Hold the key, speak, release. The transcript is cleaned of fillers and spoken punctuation by deterministic rules — no model rewriting your words — then placed at the cursor.

Voice edits on a selection

Select text, hold the key, and say a command from a fixed set: “snake case”, “camel case”, “wrap in backticks”, “bullet list”. The transform is a plain string operation, so it is instant and never surprises you.

Escape to abort

Press esc while the key is held and the audio is discarded. Nothing is transcribed, nothing is inserted.

Under the hood

How one dictation works

  1. Capture. A native helper watches for the push-to-talk key; audio records only while it is held.
  2. Transcribe. A resident whisper.cpp server turns the audio into text on the Mac's GPU.
  3. Clean. Deterministic rules strip fillers, resolve spoken punctuation, and segment long run-on speech.
  4. Check the target. A separate Accessibility helper reads the frontmost app and focused field to decide what a line break means here.
  5. Deliver. Text is written into the field, with clipboard paste and synthesised keystrokes as fallbacks.

The two helpers run as separate processes on purpose: a blocked Accessibility call can never take down the global hotkey.

Run it

Build from source

OpenStream is pre-alpha and installs from source. You need an Apple Silicon Mac on macOS 13+, Node 20+, and Xcode Command Line Tools.

# clone and install — this also compiles whisper.cpp and
# downloads the transcription + rewrite models (~1.3 GiB)
git clone https://github.com/Zazai840/openstream.git
cd openstream
npm install
npm start

OpenStream needs Microphone, Input Monitoring, and Accessibility permission. It opens on a Permissions screen with a link straight to each System Settings pane; npm run doctor runs the same check from the terminal.

Because it runs from source, every rebuild resets the macOS permission grants. When you re-grant, remove the old OpenStream entry in System Settings first, then add the new build.

Where it stands

Honest status

  • The core path — hotkey, transcription, cleanup, break-safety, delivery — runs from source today.
  • Installation, permission identity across rebuilds, and delivery recovery are still rough.
  • Codebase-aware vocabulary and semantic edits (“make this shorter”) are on the roadmap, not in the app.
  • Not signed or notarised yet — the supported install is git clone.
